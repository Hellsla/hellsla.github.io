# Concept cards, read-aloud, Yritä ensin, automatic chapter parts (from CLAUDE.md)

Siirretty `fysiikkalabra/CLAUDE.md`:stä sellaisenaan (työjono 0b, 2026-11-17). Kaikki tämän tiedoston säännöt ovat voimassa; CLAUDE.md:ssä on niiden lyhyt muoto ja viite tähän tiedostoon. Sisältö on englanniksi kuten alkuperäinen.

**Concept cards** (teacher 2026-11-03, "kortit tulevat luvun luo"): the data is `kortit/<module>.json` (fi, also used by fi-easy) and `kortit/en/<module>.json` (same ids, `luku`, `aihe`); `scripts/concept_cards.py check` validates it (LaTeX `kaava` + `kaava_puhe`, `\overline` vectors, no Unicode maths) and `stats` lists cards per chapter. The build marks bold Tiivistelmä terms that match a card (popover; a Finnish case ending is allowed, "tehoksi" → Teho) and, since 2026-11-13 (teacher, "kaikki"), the first plain mention in the theory text of each of the chapter's other cards (`concept_cards.mark_first`: same popover, plain weight; never in a heading, link, figure, formula or the chips; a build-side mark, so no review goes stale), adds chips after the Tiivistelmä list, "Kertaa luvun käsitteet" as the last part of Esimerkit, with no stage of its own in the navigation (teacher 2026-11-05; after the exit ticket with its own stage until then), the module page's "Kertauspakkasi", the Sovella page's "Varmista käsitteet" and `kasitteet.html` (the whole collection; the old `../kasitetakomo.html` redirects); all client code is `templates/kortit.js` (state in localStorage `ruukkilabra:kortit`, three "Osasin" in a row leave the deck, and the card comes back 5, then 10, then 20 days later: work queue 17d PR 1, teacher K7; fields `porras` 0–2 and `era` (local midnight, ms) in the same entry, due day read when the deck is read, no timer; one "Osasin" moves a returned card on, "Kertaa myöhemmin" starts it over; a card taken out before this change is never scheduled; no new text). Without JS the section is a plain `<dl>`. No cards before the Tiivistelmä; a language without a card file gets no section. A card `id` is permanent (students' decks are keyed by it). `test_home.py` checks the placements and the component in a browser. Authoring guide: `../KORTTIOHJE.md`.

**Ääneenluku** (teacher 2026-11-03): every page built from `templates/lesson.html` has one Kuuntele / Tauko button at the right end of the stage bar, with a menu for the speed (0,8 / 1 / 1,25) and the voice (`templates/readaloud.js`), shown only when there is a voice for the page's language. A lesson reads only Pohdinta and Teoriatiivistelmä, never a task, hint, model answer or solution; a click on a stage moves the reading there. Other pages read their visible text in page order with the Supertonic 3 voice (Nainen / Mies, `templates/vendor/supertonic3-v1`, OpenRAIL-M, run in the browser by onnxruntime-web: WebGPU or the CPU; about 145 MB fetched once and cached; teacher 2026-11-03) and, where that cannot load, the device's best voice (never a closed box, a hidden step, a figure or a simulation), formulas are spoken from `data-speech` when a formula has one, otherwise from their TeX with lang `speech` (`$F = m \cdot a$` → "F on m kertaa a"), the block, sentence and word being read are highlighted. Nothing is recorded or sent. A new unit or symbol that is read wrong is fixed in lang `speech`, never per lesson; `test_readaloud.py` checks it. A concept-card term in the text (kortit.js puts it inside `button.kc-term-btn`) is read with the text around it, so "Fysiikka on luonnontiede…" is no longer read "on luonnontiede…" (teacher 2026-11-15, "Fix it", every page and voice). **Recorded voice** (teacher 2026-11-15, work queue 5c; the voice is ElevenLabs "Oskari - Finnish", `nJ8YqEenIxs18T0Hu4QE`, chosen from three samples; the pilot is fy1-1, then FY1 and FY2 Finnish): a block of a Finnish page that has a recording is played from an mp3 instead, with the same sentence and word highlight (word times from the recording), the same speed menu and the same blocks; the other languages, courses and any block without a current recording keep the Supertonic voice and the device's voice. The recordings are made by `scripts/readaloud_audio.py <page-id>` in a developer session, never in a student's browser (the API key is the environment's network secret for api.elevenlabs.io, never written to the repository): it takes the blocks from the built page (`flSpeech.blocks()`), writes numbers and single symbols out in words for the voice only (`spoken()`), and stores one mp3 per block in the recordings repository **Hellsla/ruukkilabra-audio** (`fi/<page-id>/<hash>.mp3`; a checkout beside this repository or `RUUKKILABRA_AUDIO_DIR`; teacher 2026-11-15: the main repository never holds an mp3, as the read-aloud models live in Hellsla/ruukkilabra-models) and its manifest, the block hashes and every word's start and end time, in `assets/audio/fi/<page-id>.json` here, which `build.py` copies to `site/audio/`; `ruukkilabra-deploy.yml` checks the audio repository out and `deploy_site.py --audio` publishes its mp3 files under `audio/fi/`. Without the mp3 files (a local preview, a test, the audio repository missing) the pages read with the Supertonic or the device's voice, and no test needs an mp3. A recording is tied to the hash of the block's speech text (`textHash` in readaloud.js = `text_hash` in the script): a changed block is read by the other voices until it is recorded again, and an unchanged block is never paid for twice. A changed formula rule in lang `speech` changes the hash of every block it touches. A page that has recordings names itself in its strings (`"audio"`, `build.py`), so only that page asks for its manifest. Nothing is sent from the student's browser; the files are the site's own (ruukkilab.fi/audio/). `test_readaloud.py` checks the term, the hash and the playback of a recorded and an unrecorded block (a stand-in manifest and a silent file).

**Yritä ensin** (teacher 2026-11-03, "opiskelija yrittää ensin itse, ja ratkaisu avautuu vasta sen jälkeen"; `templates/lesson.js` part 1 and 8, `inquiry.js`; never in a lesson): a numeric task's Vastaus and Näytä ratkaisu stay in view but locked ("Avautuu, kun olet yrittänyt kerran") until one Tarkista with a number; the check accepts ±2 % or half a unit in the shown answer's last digit (`data-step` is one unit, `answers_shown.step`; half since 2026-11-10, teacher), whichever is larger (or a wider `tolerance`), and 2–5 % away is "Lähellä", not wrong; hints are all in view and open freely (teacher 2026-11-04); a plain choice shows why the chosen option is wrong (its own misconception feedback), may be changed once, then the correct option is shown with its reasoning (a prediction is still committed once); an explanation, a drawing task, a written exercise and a Sovella itsenäisesti task open their model answer, model figure and rubric after the tick "Olen tehnyt ratkaisun" (`label.drew` / `label.solved`); nothing is stored (a reload locks again); `?ratkaisut=1` opens every lock for the teacher. Each attempt dispatches `fl:attempt` {id, kind, state}.

**Every chapter gets automatically** (teacher 2026-10-29; never hand-written in a lesson): Edellinen luku / Seuraava luku in curriculum.json's teaching order over published pages only, the last to Sovella itsenäisesti (`build.py chapter_nav`, `test_chapter_nav.py`); the path over the page as a chapter menu (teacher 2026-11-08, `build.py chapter_crumbs`): "Luku 13: title ▾" ("Luku 13 ▾" on a phone) opens the module's chapters under its themes, with Edellinen / Seuraava at the row's end, so "FY3 · Luku 13" over the title shows only in print; the language links; the exercises' running numbers "luku-tehtävä" (teacher 2026-11-04: 6-1 … 6-12 over all three levels, the chapter's number being its place in curriculum.json as on the module page, shown "FY3 · Luku 6" over the title; `build.py number_label`; a review unit's tasks "1.2-1" by the unit's number on its course page; Sovella itsenäisesti keeps 1, 2, 3 on its own page; never written in a lesson, so a new or reordered exercise renumbers itself); the exercise path (core exercises marked, the first two of levels 1–2 unless `"core": true` says otherwise; levels named perus, soveltava, haastava); after a wrong check in Tarkista osaamisesi a suggestion where to practise (a task's own `"practice"` overrides it); unique SVG ids when a figure appears twice (`svgids.py`). The front page and the module pages compute what each language has published; the front page is a learning environment's start, not a product page (teacher 2026-10-31), compact enough for one desktop screen (teacher 2026-11-03, "tiivistä etusivu"): the heading (Tutki. Oivalla. Sovella.) and one line, then two columns from 700 px: the modules with lessons on the left, on the right Tulossa dimmed (the modules without lessons and those in `curriculum.json` `"_front_page".coming`) and the school's own courses; each row one link with icon, code, title and Miksi question, no counts or calls to action. The study guide (Näin opiskelet) opens the Lukuvinkit page; the front page's header links it and Sivustosta (`tietoa.html`); every page's footer is only Ruukkilabra and Tietosuoja (teacher 2026-11-04). They never show a student's progress. A module page shows each published chapter as a card (teacher 2026-11-03, "Ruukkikortit"): its opening illustration and Miksi question taken from the built page, never written twice, under the module's themes (`curriculum.json` `"themes": [{title, first}]`, translated in `content/<lang>/courses.json` `"themes"`), all in one continuous grid where a theme's name labels its first card so a short theme leaves no hole (teacher 2026-11-04); on the module page the cards are small tiles, illustration, number and title without the Miksi question, two in a row on a phone and six at 1280 px (teacher 2026-11-08, "Kuvalaatat"), while FY9, FY14 and FY10 keep the large cards; under them Kertauspakkasi, Esimerkkikoe, Haastetehtävät and Moduulin tavoitteet are tiles of the same size and look in a grid of their own, each with one shared illustration from `assets/shared/module-end/` and a count over its title, no lead text (the same on every module page and in every language, teacher 2026-11-10; `build.py end_tiles`; the deck tile's count and link follow the student's deck in kortit.js, the goals tile opens its list in place); a formula in a chapter title is LaTeX there (`"$pV = nRT$"`). The school's own courses use the same cards (teacher 2026-11-04, `scripts/cardgrid.py`, one markup for all): FY9 and FY14 units with the course's chapter heading as the label of its first unit (its question no longer under it, teacher 2026-11-08), "Luku 1.2"; FY10 investigations by topic (the bank filter moves a topic's label to its first card shown); illustration and question come from the unit's or investigation's source text. A language link to a page the other language has not published goes to that language's module page and its note `#unavailable-<id>` (teacher 2026-10-29, `test_home.py`). A text with a count uses `T.count(key, n)` and a `{"one", "other"}` value in `lang/<lang>.json`.
