# Fysiikkalabra agent office

A standalone pixel office inspired by Fysiklabbet's agent office. Open `agent-office/index.html` through a static web server. No npm install, build step, CDN or API key is needed; the font is already in this repository. The drawing lives in `office-scene.js`, separately from the history and evidence controller in `office.js`.

```sh
cd /workspace/hellsla.github.io
python3 agent-office/export_history.py
python3 -m http.server 8000 --bind 127.0.0.1
```

The exporter only reads committed Git objects and atomically replaces `agent-office/history.js`. It exports the last 200 reachable commits, including branch commits for individual review rounds and merge diffs against their first parent. It reads committed lesson content and review reports to compute historical gate evidence. It never stages, commits, switches branches, reads private Claude sessions, executes historical code, runs agents, or reads or writes lesson working files. Refresh the browser after exporting to see the new snapshot. Export manually when you want an update; there are no hooks, watchers, scheduled jobs or changes to Claude configuration. Concurrent uncommitted work is intentionally absent from the replay.

Commit times are shown in Europe/Helsinki, with daylight saving handled by Python's timezone database. Desk highlights come from changed file paths, not authenticated agent identities or session logs. Counts describe the full selected day within the exported history, not events before the replay clock. Each snapshot belongs to its particular commit; time order across branches does not establish that one version supersedes another.

Follow a lesson through development, saved automatic checks, parallel science/pedagogy reviews, the two-approval gate, and the teacher/publication desk. People carrying lesson packets illustrate the handoffs; they do not assert actual timed file transfers. Review badges use the same normalized content hash rule as `fysiikkalabra/scripts/reviews.py`, including simulation test specifications: both reports must say PASS and match the selected commit's lesson hash. Missing, invalid, failed or stale reports keep this gate closed. Content changes can invalidate earlier PASS reports. A matching legacy marker is a separate prototype exception, explicitly labelled, not a two-review approval.

The connected floor plan has separate development, science and pedagogy rooms, a teacher's planning room, an automatic check runner, the review coordinator, an occupied human publication desk and the website. The teacher briefs the developer; the review coordinator delivers the reviewed packet to the decision-maker and returns to the review desk. A website courier then visits the publication desk. Couriers carry packets labelled with the chosen lesson ID: brief, lesson, reviewer copy, report, reviewed material or revision request. Failed and stale approvals return the illustrated work to development; missing reports keep the desk waiting. Dashed routes and arrows are omitted; the couriers themselves show each handoff. Deployment stays unverified. These are actual project roles and automated stations; no additional agents are launched or invented.

People have distinct skin tones, hairstyles, facial hair, glasses, clothing, heights and accessories (developer headphones and a courier satchel). Motion uses elapsed time on each animation frame, fractional positions, rounded path corners, directional poses, and eased starts/stops at handoffs. A pause, reduced-motion choice, hidden tab or open dialog stops the walking. Person and packet labels stay clear of faces. The scene repaints less often when idle.

The website courier waits briefly for the decision, then returns without material when approval is unknown. The renderer accepts an explicit `publicationDecision: {status: "approved", contentHash: "<current lesson hash>"}` on a lesson snapshot as recorded approval evidence. Only a matching approval and both current passing reviews permit an APPROVED pickup. Existing exported history does not contain human approval evidence, so merges and existing HTML never trigger collection. Approval for an older hash is insufficient, and collection never claims successful deployment.

Science and pedagogy work independently in parallel, with staggered copy collection, different review durations and separate report deliveries. Which role finishes first varies deterministically by lesson version; these timings are illustrative, not measured session durations. Room labels distinguish recorded verdicts from the current walkthrough activity. The review desk counts delivered reports and visibly waits at 1/2; it becomes READY only after both illustrated deliveries and two current recorded PASS verdicts. Report packets carry PASS, FAIL, STALE or INVALID labels. A failed, stale or invalid report leads to a REVISE handoff; a missing report keeps the desk waiting without inventing a report or publication handoff. Fixing a version requires new checks and reviews, not reuse of its previous approvals.

Playback has two explicit modes. **Lesson journey** (the default) loops the illustrated handoffs while keeping the recorded commit and clock fixed. **Day history** advances through the recorded commits and their evidence. Both start paused. **Next handoff** steps through the six parts of the journey and each reviewer's separate pickup, completion and report arrival, including with reduced motion; **Next commit** changes the historical snapshot. **Office zoom** enlarges the drawing inside its scrollable viewport, including on phones. Every room or station can be inspected by clicking it or using its role button.

The review coordinator is an ordinary office colleague at a desk with two review results. Its READY, WAITING or REVISE note follows the selected snapshot. There is no uniform, badge, stop paddle or barrier. The publication desk always has a seated colleague; the review coordinator delivers material beside this person, and the website courier visits afterward. These figures represent office roles rather than a claim about the number of real participants. The review colleague personifies the automatic rule in `reviews.py`, not an additional running agent. Every colleague can be inspected by clicking them or using their role buttons.

Saved `review/checks.txt` reports have no content hash, so check freshness and CI success stay unknown; a matching review pair alone never claims all publication requirements passed. Presence in committed `site/` means only that an HTML page exists in that snapshot, not that it matches a fresh render or is deployed. A merge does not identify its human approver or prove deployment. The office visualizes these rules but does not enforce or change branch protection, CI, builds or publishing settings.

The page includes day and lesson selection, pause/play, playback speed, next event, a keyboard-accessible time slider and role buttons, clickable desks and commit entries, fullscreen, and a still-scene control. It respects reduced-motion preferences and starts paused; playback and file-packet animation pause together. All commit titles and lesson metadata are rendered as text. The reference upload's external scripts and data were missing; this implementation has its own canvas art, styles and scripts, and includes no third-party analytics.

All implementation and generated metadata live in this directory. No changes are needed in lesson sources, simulations, shared templates, CI, or `.claude/` files. There is deliberately no link added to the public homepage. Publishing or merging remains a separate decision.
